## FOLLOW THE PROJECT (section 13)

- `api/subscribe.js` — `POST /api/subscribe`. Validates the address, rate-limits per IP (8/hour, IP stored only as a SHA-256 hash), stores it in Neon PostgreSQL and sends a confirmation email through Resend from `utaki.me`.
  - The row is written inside a transaction that commits only after Resend accepts the email. If sending fails, nothing is stored and the visitor sees an error.
  - Responses: `subscribed` (201), `duplicate` (200, no email re-sent), `invalid_email` (400, bad format or rejected by Resend), `rate_limited` (429), `send_failed` (502), `storage_error` (502), `not_configured` (503).
- `api/unsubscribe.js` — link in every confirmation email (and `List-Unsubscribe` one-click header). `GET` shows a confirm button, `POST` sets `status = 'unsubscribed'`.
- `api/config.js` — `GET /api/config` returns `{ subscribeEnabled, instagramUrl }` (no secrets). `subscribeEnabled` is true only when both `DATABASE_URL` and `RESEND_API_KEY` are set.
- `api/_email.js` — the confirmation email (English first, Japanese second). `RESEND_API_KEY` is used only in the server-side Authorization header and never logged.
- Without a valid `INSTAGRAM_URL` (`https://instagram.com/...`) the Instagram button stays disabled with no link.

### Database

`db/schema.sql` creates two tables (and nothing else):

| table | purpose |
| --- | --- |
| `twt_subscribers` | `email` (unique, lowercase), `status` (`subscribed` / `unsubscribed`), `source`, `subscribed_at`, `updated_at`, `confirmation_sent_at`, `unsubscribe_token` |
| `twt_subscribe_attempts` | per-IP-hash attempt counter for rate limiting |

The function runs this schema automatically (`CREATE TABLE IF NOT EXISTS`) on first use. You can also run it yourself in the Neon SQL Editor.

List subscribers (Neon SQL Editor):

```sql
SELECT email, subscribed_at FROM twt_subscribers WHERE status = 'subscribed' ORDER BY subscribed_at;
```

Environment variables: see `.env.example`. Subscriber data lives only in the database, never in this repository.

## Essays (second layer)

- The LP has one entry point, `#the-six-essays`, between 11 SECRET and 12 END (Issue #2). It links to the reading index `/essays/`.
- `/essays/` lists the six essays in order; `/essays/01/` … `/essays/06/` are the essays, with previous / next navigation (06 → back to the index) and a return to the LP entry.
- All pages are generated by `npm run build:essays` from `content/essays/NN.md` (see `content/essays/README.md`); titles are in `content/essays/essays.json`.
- A missing manuscript produces a "MANUSCRIPT PENDING / 原稿未配置" page with `noindex`. Essay 06 must end with `TIME WILL TELL.` or the build fails.
- English translations are not approved yet; pages carry an "ENGLISH TRANSLATION — PENDING EDITORIAL REVIEW" marker.

## Two-part LP

1. **Part one** (hero → NOTHING) lives directly in `index.html`. Chapter numbers are hidden; only the quiet section names remain.
2. **Interlude** — `#the-six-essays` (ESSAYS / 思考の記録) sits between NOTHING and the field log: six titles, each linking directly to `/essays/NN/`, plus a link to the `/essays/` index. It is generated by `npm run build:essays` from `content/essays/essays.json` (`category` is the small label shown on the LP). The LP can be scrolled straight past it.
3. **Part two — FIELD LOG** is generated. Do not edit it inside `index.html`; edit `content/log/` and run `npm run build:log`.

### Updating the field log

- `content/log/log.json` — ordered entries. Numbering (`LOG 01`, `LOG 02` … no fixed total) and the FIELD LOG index follow this order automatically.
  - `file`: the entry's markup in `content/log/` (inner content only — the wrapper, number and margin are generated).
  - `title`, `labelledby` (id of the entry's heading), `classes` (e.g. `sec-dark`), `layout` (`sec` or `end`), optional `id`.
  - `updated`: `"YYYY-MM-DD"` or `null`. It is shown as `UPDATED …` only when set. Set it to the real date the entry's content changed — never a placeholder.
- Add an entry: create `content/log/NN-name.html`, add it to `log.json`, run `npm run build:log`.
- The build only rewrites the block between `<!-- LOG:START -->` and `<!-- LOG:END -->`.
